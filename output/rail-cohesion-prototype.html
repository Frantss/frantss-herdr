Code-only notes

These simplifications change no visible behavior, so the preview does not show them.

S1 · One shared agent-list refresh

The rail, the thread picker and the new menu each refresh the agent list and store it under frantss.agents. Use one machine-keyed refresh helper and one state key.

Boundary: keep loading and error behavior per surface. Do not add a cache or retry framework.

S2 · One saved-workspace contract

The saved-workspace key and type are repeated in the rail and in frantss-workspace. Share one contract.

Boundary: do not extend the schema to remote machines without a requirement.

S3 · Shared space naming and rename prompt

The rail, toolbar and menu each build space display names and rename prompts. Share the naming and prompt construction.

Boundary: keep pane aliases, tab names and space names distinct.

S4 · One small openThread helper

Thread-popup setup is repeated for the workspace + and the space +. Extract a helper only if it makes the explicit target simpler.

Boundary: keep the real differences in machine, folder, existing space and repo eligibility.

S5 · Delete the checkout path convention

F4 replaces the /.herdr/worktrees/ path test with discovered checkout state. Delete the path test.

Boundary: keep the uncertainty visible while the repository lookup is pending.

S6 · Small shared selectable list

Row and keyboard behavior differ across three popups. Reuse one small native selectable-list pattern if F2 shows enough common behavior.

Boundary: no generic action registry or menu framework.

Alternative B · Merge the popups into frantss-menu

Add thread, workspace and composite-space modes to frantss-menu, migrate every caller, then delete frantss-thread and frantss-workspace.

This is not a switch: the visible behavior can match approach A. B changes code ownership, needs separate approval, and risks state leaking between modes and popup sizes (260×420, 220×120, 320×440). pnpm check:mods alone cannot prove that dynamic callers are gone.
