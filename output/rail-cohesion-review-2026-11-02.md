# Rail cohesion review and proposal

Date: 2026-11-02
Reviewer: Claude Opus 5.5, high effort, through Herdr Core (`rail-cohesion-review`, t197). Coordinator checked consequential findings against source and inspected the running native app.
Status: proposal only. No application code, layout, theme, settings, or live workspace changes.

## Recommendation

Keep the current rail structure. Make actions stable when rows compress, use the same keyboard contract throughout, and make thread targets and Resume eligibility explicit. Extract duplicated behavior only where it reduces maintenance. Do not merge the popup mods first.

The rail has two useful views of the same work: Workspaces shows location; agent groups show attention. Preserve both views, their shared terminal identity, and the existing navigation order. Cohesion means that selecting or acting on the same object has consistent effects in either view, not that every feature must live in one list.

## Two viable approaches

### A. Targeted cohesion fixes, recommended

Keep the current mods and rail sections. Extend menu targets to retain parent context, use Git checkout classification, align Resume/Interrupt eligibility, and complete row/picker keyboard behavior. Extract S1–S5 only where they reduce touched duplication.

Verification: existing behavior tests for compression/splitting and menu actions must cover preserved consumer-visible behavior, not source text or copied props. Add focused edge coverage for external worktree targeting and missing-folder Resume. After implementation run `pnpm test`, `pnpm check`, and `pnpm check:mods`; run `pnpm run link` as required for mod changes. Then execute the acceptance scenarios above in the native app and inspect `herdr-app status` and screenshots. Tests and the native initial-render checker do not prove later interactions or geometry.

Risks: a larger composite menu can overflow its 440px maximum; separate space actions clearly and verify scrolling/keyboard reachability. New focus handles can churn when rows regroup; reuse stable IDs and the existing worktree focus lifecycle. Checkout lookups are asynchronous; avoid presenting an unverified target as the main checkout. Preserve all worktree safety checks and shared unread/pin semantics.

Coding standards: KISS and YAGNI favor bounded fixes. DIE supports S1–S5. Keep action execution in its existing owner and pass explicit context rather than coupling renderers to unrelated state. No permanent compatibility aliases or speculative frameworks.

### B. Consolidate rail popups into `frantss-menu`

Add thread/workspace/composite-space modes to the existing menu mod. Migrate every caller, then delete the obsolete `frantss-thread` and `frantss-workspace` mods. This is viable but cross-cutting; it requires separate implementation approval.

Verification: run A's acceptance scenarios for every entry point, including agent-graph callers. Check known-agent loading and failure states, focus restoration, action targeting, popup sizing and all menu modes. Search all overlay callers for obsolete mod names in addition to running native checks; `pnpm check:mods` alone cannot prove that dynamic references are gone.

Risks: combines async launch discovery, workspace persistence and terminal actions in one mod; fewer files do not necessarily mean higher cohesion. Popup dimensions currently differ (260×420, 220×120 and 320×440), and state can leak between modes. Mitigate with explicit mode-specific data, complete caller migration and behavior verification. Do not choose B solely to remove two directories.

## Rejected approaches

- Replace compressed rows with space-only menus: loses useful pane and agent actions.
- Remove either the workspace tree or agent attention list: each answers a different question, and both already share terminal identity.
- Treat close, settle, park, kill, forget history and remove worktree as one generic action: their state transitions and safety consequences differ.
- Redesign colors, fonts or spacing without a demonstrated task failure: no measured visual defect supports that scope.
- Add remote persistence, exact-session resume, offline indicators or a global action framework speculatively: verify the missing requirement first.
